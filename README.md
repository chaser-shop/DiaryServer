# Щоденник студента — вебверсія + сервер (Node.js, MongoDB, Web Push)

Той самий щоденник, що й на iPhone, але у браузері: розклад, посилання на пари, домашнє з підтвердженням адміністратором і **сповіщення з сервера**. Друзі просто відкривають посилання, вводять ПІБ — і все. Сервер сумісний з вашим iOS-застосунком (ті самі `/api/...`), тож iPhone-версія і веб працюють з **однією базою**.

## Що всередині

```
server.js            сервер: REST API + розсилка сповіщень + віддача сайту
public/              вебзастосунок (PWA, без збірки)
  index.html, app.js, style.css, schedule.js (розбір .xls/.csv), sw.js, manifest, icons/
seed/                початкові дані рейтингу (імпортуються автоматично один раз)
package.json         залежності: mongodb, web-push (більше нічого)
render.yaml          готовий конфіг для Render
.env.example         усі змінні середовища
```

## Запуск за 10 хвилин

### 1. MongoDB (безкоштовно)
1. Зареєструйтесь на [mongodb.com/atlas](https://www.mongodb.com/atlas) → створіть безкоштовний кластер (M0).
2. *Database Access* → створіть користувача з паролем. *Network Access* → додайте `0.0.0.0/0`.
3. *Connect → Drivers* → скопіюйте рядок `mongodb+srv://…` (підставте свій пароль).

### 2. Сервер (Render)
1. Завантажте цю папку в GitHub-репозиторій.
2. На [render.com](https://render.com): *New → Web Service* → оберіть репозиторій (або *Blueprint* — підхопить `render.yaml`).
3. Build: `npm install`, Start: `npm start`.
4. Змінні середовища:

| Змінна | Що вказати |
|---|---|
| `MONGODB_URI` | рядок з Atlas (**обов'язково**) |
| `ADMIN_NAMES` | ваш ПІБ повністю (кілька — через кому). Без неї адміном стане перший, хто увійде |
| `VAPID_SUBJECT` | `mailto:` + **реальна** пошта (потрібно для сповіщень; з фіктивною на кшталт example.com Apple відповідає 403) |
| `ADMIN_PASSWORD` | необов'язково: пароль, щоб адмін міг увійти з **нового** пристрою |

Ключі сповіщень (VAPID) і секрет токенів сервер створює сам і зберігає в MongoDB — нічого генерувати не треба.

Локально: `npm install`, скопіюйте `.env.example` у `.env`, `export $(cat .env | xargs) && npm start`, відкрийте `http://localhost:3000`.

### 3. Перший вхід
Відкрийте адресу сервера, увійдіть під своїм ПІБ (ви — адмін) → *Налаштування → Завантажити розклад* (.xls з порталу, .xlsx або .csv). Далі *Предмети й посилання* — вкажіть повні назви й Zoom/Meet.

### 4. Поділитися з друзями
*Налаштування → Поділитися посиланням* — і надішліть адресу. Кожен вводить свій ПІБ. Перший пристрій закріплюється одразу; з кожного наступного людина натискає «Увійти» — адміністратору приходить запит (і сповіщення), він підтверджує його в *Налаштування → Учасники й пристрої*, і вхід на новому пристрої відбувається сам. Ліміт — 5 пристроїв на людину (`MAX_DEVICES`). Втрачений пристрій видаляється зі списку там же.

## Сповіщення

Приходять **з сервера** (Web Push), тому працюють і при закритому щоденнику:
- «Пара через N хв — заходь!» (N — у налаштуваннях кожного, 1–15)
- «Пара закінчилась — що задали?»
- «Нове домашнє» після підтвердження; адміну — «Домашнє на підтвердження»

**iPhone (iOS 16.4+):** відкрийте сайт у **Safari** → «Поділитися» → «На початковий екран» → запустіть **з іконки** → *Налаштування → Увімкнути сповіщення*. У вкладці Safari iOS сповіщень не дозволяє.
**Android / ПК:** Chrome — просто *Увімкнути сповіщення* (можна ще «Встановити застосунок»).

## Важливо знати

- **Безкоштовний Render «засинає» через 15 хв без запитів — тоді сповіщення не йдуть.** Сервер сам себе «будить» кожні 10 хв (на Render це вмикається автоматично, `KEEP_ALIVE=0` вимкне), але надійніше — платний тариф або зовнішній пінг (UptimeRobot) на `/healthz` кожні 5 хв.
- Час пар — київський (`APP_TZ`, за замовчуванням `Europe/Kyiv`).
- iPhone-застосунок: у `APIClient.swift` змініть `defaultServer` на адресу нового сервера (або впишіть її на екрані входу в розділі «Сервер»). **Адміну краще першому увійти саме з iPhone-застосунку**, якщо задаєте `ADMIN_PASSWORD`: застосунок пароль не надсилає (це лише для входу з нових пристроїв).
- Дані зі старого сервера не переносяться автоматично (його коду в архіві не було): розклад завантажте заново, домашнє внесете знову.
- Вебверсія показує час у поясі пристрою; домашнє «виконано» зберігається лише на пристрої (як і в iOS-версії).
- Для читання `.xls` браузер адміна один раз підтягує бібліотеку SheetJS з cdnjs; `.csv` працює без неї.

## Рейтинг

- **Звідки бали:** адміністратор завантажує Excel-таблицю (.xlsx / .xls / .csv) — так само, як розклад: *Адмін → Таблиця рейтингу → Завантажити таблицю*. Файл розбирається в браузері (`public/rating.js`) і відправляється на сервер (`PUT /api/admin/rating/import`).
- **Формат таблиці:** колонка «Прізвище, ім’я та по батькові» (допускається «ПІБ»), правіше — по колонці на кожен предмет (СПОУ, ТіДтП, Укр, СФП, КПУ, Інформ, вступ, Англ — назви беруться із заголовків). Колонки «№», «Разом», «Сума», «Місце» ігноруються. Дужки в ПІБ (наприклад, «(староста)») стають позначкою біля імені. Порожня клітинка — балів немає.
- **Новий файл повністю оновлює рейтинг:** бали наявних студентів змінюються, нових додано, тих, кого немає у файлі, видалено.
- **Студент:** вкладка «Рейтинг» → випадаючий список «Загальний рейтинг (сума)» або будь-який предмет. Бачить своє місце, подіум (топ-3) і рейтинг своєї групи; розбивку за предметами бачить лише для призначеного профілю.
- **Прив’язка до студента:** в картці учасника адміністратор задає групу, роль і окремо студента рейтингу. У випадаючому списку студента показані всі ПІБ із завантаженого рейтингу. Вибір студента застосовується до всіх наявних пристроїв акаунта; для окремого пристрою можна змінити прив’язку індивідуально. Нові пристрої успадковують студента акаунта. У головному меню та вкладці «Рейтинг» відображається рейтинг призначеного студента. Без призначення чужий рейтинг недоступний.
- Місця: за спаданням балів; однакові бали — однакове місце; без балів (за обраним предметом) — без місця, внизу.
- Адмін також може вручну додати/видалити студента чи змінити бали в *Керування рейтингом*.
- Перша таблиця (група «101 СПД», 33 студенти) імпортується з `seed/rating-101-spd.json` при першому запуску.

API: `GET /api/rating[?subject=СПОУ]` · `PUT /api/admin/rating/import` · `POST|PATCH|DELETE /api/admin/rating[/:id]` · `GET|POST|PATCH /api/admin/groups`, `DELETE /api/admin/groups/:name[?moveTo=група]` · `POST /api/admin/users/:id/devices/:key/student` та `GET /api/admin/rating-students` (усі `/api/admin/*` — адмін).

**Групи** (*Адміністрування → Групи*): створення, перейменування й видалення. Назва — 2–40 символів, однакові назви (без урахування регістру) не допускаються. Групу зі студентами чи обліковими записами можна видалити лише з перенесенням до іншої групи — записи, бали, історія, статистика й прив’язки зберігаються; якщо в цільовій групі вже є студент із тим самим ПІБ, видалення відхиляється. Групу, яку заповнює Google-таблиця, видалити не можна, а після перейменування синхронізація оновлює її під новою назвою.

## API (для довідки)
`POST /api/auth/login` · `GET /api/sync` · `PUT /api/schedule|subjects|teachers` (адмін) · `POST|PATCH|DELETE /api/homework[/:id]`, `POST /api/homework/:id/approve|reject` (адмін) · `/api/push/*` · `/api/admin/users` (адмін) · `GET /healthz`


## Автоматичне оновлення рейтингу з Google Sheets

Сервер автоматично читає аркуш Google-таблиці та оновлює рейтинг кожні 2 хвилини; відкриті сторінки застосунку підтягують нові дані самі, без ручного оновлення. Кожна перевірка звіряє всю таблицю з базою й записує лише справжні відмінності: ПІБ, виправлене в тому самому рядку («№ з/п», різниця в 1–2 літери), не створює дубліката; студент, якого архівував адміністратор, не відновлюється таблицею; якщо таблиця недоступна, адміністратор і студенти бачать повідомлення про помилку й дату останніх збережених даних. Для таблиці, переданої в цьому проєкті, вже встановлено Spreadsheet ID. У Render додайте/перевірте такі змінні:

| Змінна | Значення | Призначення |
|---|---|---|
| `GOOGLE_SHEET_ID` | `1grET3-MHCkBXqrBrHL1BIiUnAks0Kh3P4MuOijcPykY` | ID Google-таблиці |
| `GOOGLE_SHEET_GID` | `447170421` | ID аркуша (gid з URL потрібної вкладки, тут — «101_СПД_2026») |
| `GOOGLE_SHEET_GROUP` | `101 СПД` | Група, до якої імпортувати студентів |
| `GOOGLE_SHEET_INTERVAL_MS` | `120000` | Інтервал перевірки в мілісекундах (2 хвилини, мінімум 60000) |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | JSON ключ сервісного акаунта | Секрет для приватного читання Google-таблиці |

**Приватний доступ до таблиці (рекомендовано):** створіть Google Cloud service account, увімкніть Google Sheets API, створіть JSON-ключ і додайте його в Render як секретну змінну `GOOGLE_SERVICE_ACCOUNT_JSON` (вставте весь JSON одним значенням). Поділіться самою таблицею лише з email сервісного акаунта з правом **Читач**. Не вмикайте загальний доступ «Усі, хто має посилання»: таблиця містить ПІБ та оцінки студентів. Сервер використовує лише scope `spreadsheets.readonly` і не змінює Google-таблицю.

**Формат:** у таблиці має бути заголовок колонки «ПІБ» або «Прізвище…», а праворуч — окремі колонки предметів. Підсумкові колонки «Разом», «Сума», «Місце» ігноруються; загальна сума обчислюється сервером. Перші 30 рядків перевіряються на пошук заголовка, тому над заголовком можуть бути назва/дата.

Після успішного читання сервер оновлює бали, додає нових студентів і прибирає тих, кого вже немає в таблиці. Ідентифікатори наявних студентів зберігаються, тому прив’язки пристроїв не губляться при звичайному оновленні балів. Якщо Google тимчасово недоступний або структура таблиці помилкова, останній успішний рейтинг зберігається, а помилка й час останнього оновлення показуються адміністратору в блоці «Таблиця рейтингу».
